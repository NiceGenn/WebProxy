# Сборщик WebProxy из Telegram

Сборщик читает публичный канал `@webproxy` через Telethon с пользовательской сессией. Он сохраняет пары `server + secret`, источник и время наблюдения в SQLite на Docker volume `webproxy_tg_data`. Сайт загружает опубликованный `site/webproxy.json` и добавляет пары к исходному списку. Проверка HTTPS-доступности остаётся отдельным действием в браузере. Наличие ссылки в JSON **не означает**, что прокси работает.

## Устройство и публикация

При первой авторизации сборщик читает последние `INITIAL_DEPTH` сообщений (по умолчанию 500). Дальше он принимает новые сообщения и правки, а после перезапуска читает все новые сообщения с сохранённого ID. Последние `RESCAN_DEPTH` сообщений перечитываются после запуска и каждые `POLL_SECONDS` секунд, чтобы обнаружить правки, сделанные во время простоя. Более старые правки за пределами этого окна при простое не обнаружатся автоматически; при необходимости увеличьте `RESCAN_DEPTH`.

Ссылки берутся из текста, Telegram URL entities и кнопок. При правке сообщения новая пара добавляется, а уже найденная пара остаётся в историческом списке: давность публикации не является признаком отказа. `first_seen` и `last_seen` означают время первого и последнего *изменившего данные* наблюдения, а `message_date` — дату сообщения-источника. Список уникален по паре `server + secret`. JSON заменяется атомарно; при сбое Telegram предыдущий файл и SQLite остаются доступными.

Варианты доставки на Pages: отдельный серверный API потребовал бы публичный endpoint и CORS; Git push по SSH deploy key подходит, но усложняет управление ключом и Git. Выбран GitHub Contents API с fine-grained PAT: сборщик загружает **только** `site/webproxy.json`, если содержимое изменилось. Запись с PAT запускает существующий Pages workflow по `push` в `main`. Встроенный `GITHUB_TOKEN` для этого не подходит: его push обычно не запускает следующий workflow. Время на сайте обозначает **последний успешный опубликованный сбор**; при отсутствии новых данных оно не обновляется, чтобы не делать пустых публикаций. Локальное время последнего успешного контакта с Telegram проверяет healthcheck.

## Подготовка

1. Убедитесь, что Docker Desktop/Engine работает, затем откройте PowerShell в корне репозитория. Достаточно `docker compose version` и `docker info` без ошибки.
2. На [my.telegram.org](https://my.telegram.org/) войдите своим Telegram-номером, откройте **API development tools**, создайте приложение и получите `api_id` и `api_hash`. Это ключи пользовательского API, не токен бота. Не присылайте их, номер, код, пароль или файл сессии в чат.
3. Скопируйте `.env.example` в `.env`: `Copy-Item .env.example .env`. Откройте `.env` локально и впишите `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`. Файл исключён из Git. Остальные значения при необходимости измените локально.
4. Соберите образ: `docker compose build`.
5. Отдельно проведите интерактивную авторизацию: `docker compose run --rm collector python -m collector auth`. В терминале введите номер, код Telegram и при запросе пароль 2FA. Ввод всех трёх значений скрыт; не вставляйте их в историю команд. Проверьте появление сообщения об успешном сохранении сессии. Файл `/data/telegram.session` остаётся только в Docker volume.
6. Запустите сборщик: `docker compose up -d`. Проверяйте `docker compose ps` и `docker compose logs --tail=100 collector`. Ожидаемое сообщение — `Telegram collection successful`. Не вставляйте в баг-репорты файлы volume или содержимое `.env`.

Без GitHub PAT сборщик работает локально и экспортирует `/data/webproxy.json`, но не публикует его. Для проверки экспорта: `docker compose exec collector python -m json.tool /data/webproxy.json`. Этот JSON содержит публично распространяемые ссылки и их `secret`; это **не** Telegram-сессия и не ключ GitHub.

## Доступ к GitHub

Создайте fine-grained personal access token для владельца `NiceGenn` только на репозиторий `WebProxy` с разрешением **Contents: Read and write**. Это минимальное разрешение для чтения SHA файла и записи `site/webproxy.json`; права на Actions, Pages, Secrets и другие репозитории не нужны. Задайте срок действия и отзовите токен, когда он больше не нужен. Если в репозитории включены правила ветки, разрешите этому аккаунту запись в `main` или используйте отдельную разрешённую ветку и скорректируйте workflow.

Сохраните PAT в приватный volume интерактивно: `docker compose run --rm collector python -m collector token`. Токен не вводится в командную строку, `.env` или Git. Перезапустите контейнер: `docker compose restart collector`. Публикация произойдёт при следующем успешном цикле; проверяйте Actions и сайт. Сам Docker volume содержит и сессию, и PAT: не подключайте его к веб-серверу и не экспортируйте публично.

## Обновление и восстановление

Для обновления кода: получите изменения Git, затем `docker compose up -d --build`. Volume сохраняется, повторная авторизация не нужна, пока Telegram не отзовёт сессию. `restart: unless-stopped` восстанавливает контейнер после сбоя и перезагрузки Docker. Healthcheck считает сборщик здоровым, только если последний успешный контакт с Telegram укладывается в три интервала опроса плюс две минуты. При FloodWait сборщик ждёт указанную Telegram задержку; при временной ошибке пробует снова. В логах выводятся категории ошибок, без учётных данных.

Для согласованной резервной копии остановите сервис: `docker compose stop collector`. Из PowerShell в корне проекта выполните `docker run --rm -v webproxy_tg_data:/data:ro -v "${PWD}:/backup" alpine tar -czf /backup/collector-backup.tar.gz -C /data .`, затем `docker compose up -d`. Архив содержит Telegram-сессию, SQLite и PAT: храните его как секрет, вне GitHub и веб-каталога. Проверьте архив командой `tar -tzf collector-backup.tar.gz`.

Для восстановления **после сохранения отдельной копии текущего volume** остановите сервис, затем в подготовленный volume выполните `docker run --rm -v webproxy_tg_data:/data -v "${PWD}:/backup:ro" alpine tar -xzf /backup/collector-backup.tar.gz -C /data` и запустите `docker compose up -d`. Если восстанавливаете на другом хосте, проверьте владельца файлов: контейнер работает от UID 10001. Не копируйте открытый SQLite-файл во время записи; используйте остановку сервиса или штатный SQLite backup.

Если GitHub или Telegram временно недоступны, ранее опубликованный список остаётся на Pages. При ошибке загрузки JSON сайт показывает 32 исходные ссылки и сообщает о недоступности обновлений. Сайт отображает время опубликованного сбора, а не выдаёт найденные ссылки за проверенные прокси.
