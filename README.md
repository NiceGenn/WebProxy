# WebProxy Monitor

Сборщик ссылок из публичного Telegram-канала: [инструкция по Docker, авторизации, публикации и восстановлению](docs/collector.md). Исходные 32 ссылки остаются резервным списком сайта.

Мини-сайт на русском с 32 исходными ссылками WebProxy. Поиск, фильтры, сортировка по номеру, серверу, статусу, времени ответа и доле ответов в истории, история последних 12 проверок, автопроверка раз в минуту, копирование, экспорт и добавление ссылок. Адаптирован для телефона. Без зависимостей и внешних шрифтов.

Сортировка доступна по нажатию на заголовки столбцов: повторное нажатие меняет направление, стрелка показывает текущий порядок. Выпадающий список синхронизирован с заголовками и доступен на телефоне. Серверы без измерений остаются внизу при сортировке времени и истории в любом направлении.

## Локальный запуск

Нужен Node.js 20 или новее (в облачной среде используется Node.js 24).

```sh
npm test
npm run dev
```

Сервер разработки слушает порт 4173; изменить его можно переменной `PORT`. Все публикуемые файлы находятся в `site/`. Сборка и установка пакетов не требуются. Открывать сайт нужно через HTTP/HTTPS, а не как файл: используются JavaScript-модули.

## GitHub Pages

1. Поместите файлы проекта в ветку `main` репозитория `NiceGenn/WebProxy`.
2. В GitHub откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Workflow **Publish WebProxy Monitor** автоматически выполнит тесты и опубликует папку `site/` при push в `main`. Для повторного запуска используйте **Actions → Publish WebProxy Monitor → Run workflow**.
4. После успешного deploy адрес будет **https://nicegenn.github.io/WebProxy/**. Ссылка появится в результате workflow и в Settings → Pages.

Также поддерживается **Deploy from a branch → main → / (root)**: корневой `index.html` открывает приложение в `site/`, а `.nojekyll` отключает обработку Jekyll. В этом режиме адрес `https://nicegenn.github.io/WebProxy/` перенаправляет на `https://nicegenn.github.io/WebProxy/site/`.

Ресурсы подключены относительными путями, поэтому сайт работает в подпапке репозитория. Не требуется backend, API-ключ или секрет GitHub в коде. Если репозиторий приватный, доступность Pages зависит от тарифа GitHub.

## Подключение в Telegram

Кнопка «Подключить» открывает диалог с сервером, ключом и прямой ссылкой. Кнопка «Открыть Telegram» в этом диалоге синхронно вызывает `window.location.assign` с `tg://webproxy?server=…&secret=…` во время клика: она передаёт исходные сервер и ключ обработчику WebProxy приложения Telegram. Веб-страница `https://t.me/webproxy?...` может открывать канал `@webproxy`, поэтому для запуска приложения применяется прямой deep link без новой вкладки.

Браузер может запросить разрешение на запуск Telegram. Нужны установленное приложение, поддержка WebProxy и зарегистрированный обработчик протокола `tg:`. Сайт не может проверить, открылось ли нативное окно, и не подтверждает подключение за пользователя. Диалог на сайте показывает передаваемые параметры и инструкции: при блокировке встроенным браузером откройте сайт в обычном браузере или скопируйте прямую `tg://webproxy` ссылку из диалога и откройте её в адресной строке обычного браузера. На Windows также можно вставить эту ссылку в окно **Win+R** и нажать Enter: это передаст её зарегистрированному обработчику `tg:` напрямую, без браузерной страницы `t.me`. Если открывается канал вместо подтверждения прокси, проверьте прямую ссылку через Win+R: успешный запуск подтверждает поддержку в установленном клиенте, и тогда следует проверить передачу ссылки браузером. Сам сайт не преобразует команду в `tg://resolve` или страницу канала `t.me`. Копирование в окне подключения использует `tg://webproxy`; кнопки копирования в строках и экспорт сохраняют исходный HTTPS-формат ссылок. HTML и импорты модулей содержат версию ресурсов, чтобы новая публикация не использовала закэшированные старые обработчики.

Формат подтверждён обработчиком `ApplyWebProxy` и преобразованием HTTPS-ссылок в [исходниках Telegram Desktop](https://github.com/telegramdesktop/tdesktop/blob/v7.3.1/Telegram/SourceFiles/core/local_url_handlers.cpp).

## Что означает результат

Это **проверка HTTPS-доступности**, а не тест протокола Telegram. Браузер отправляет `GET https://<server>/` в режиме `no-cors`, с таймаутом 8 секунд и максимум 4 параллельными запросами. Secret не отправляется на проверяемый домен. Полученный opaque-ответ означает только, что запрос завершился: HTTP-код и содержимое нельзя прочитать, и ответ 403/404/500 также может считаться полученным.

«Нет ответа» может означать сетевой сбой, ошибку сертификата, ограничения браузера или блокировку. Время измеряется от начала запроса до ответа и включает DNS/TLS; оно не равно ICMP ping. Само подключение и аутентификацию WebProxy проверяйте в Telegram. Для полноценного протокольного мониторинга нужен отдельный backend; GitHub Pages выполняет только статический код.

История, дополнительные ссылки и результаты сохраняются в localStorage на устройстве посетителя. После перезагрузки показаны предыдущие результаты с временем проверки; сайт не выдаёт их за новые. Сохранённые ссылки содержат secret, а исходные ссылки доступны любому посетителю сайта. Автопроверка по умолчанию выключена и приостанавливается в скрытой вкладке. Экспорт выгружает ссылки, видимые с текущим фильтром и поиском.

## Проверки

`npm test` запускает тесты сохранности списка, проверки вводимых ссылок, поиска/сортировки, параметров запроса, таймаута и отмены. Для работы в ограниченной облачной сети нужны HTTPS-домены из `site/proxies.js`. Реальные браузерные результаты зависят от сети посетителя, разрешений и блокировщиков.
